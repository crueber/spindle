Edits go through Configuration: add, change or revoke a row under server.auth.tokens. Each row may set name (the stable label used above and in the last-used record), expires_at (RFC 3339; an expired row is refused with a 401, so git erases it) and write. server.auth.tokens requires a restart, and a row whose credential resolves to nothing is dropped at startup. No API route mints or revokes a static token, so this page offers no such control.

Rotation without downtime is a rolling deploy. Add the NEW row for the same principal, roll a second instance with it (the old token still works while both rows are configured), update clients, then remove the OLD row and roll again. A single-instance restart is only downtime-free if your orchestrator overlaps old and new processes; there is no in-process config reload, so restarting one instance in place is a brief outage for its in-flight requests.

Last use is recorded at most once per token per five minutes, asynchronously: a write failure only leaves the column stale, never fails a request. wgt_ personal access tokens are a different credential: a signed-in user mints one at /_auth/tokens; rotating server.auth.session_secret revokes every session and wgt_ token at once.

Discovery test

Fetches <issuer>/.well-known/openid-configuration and its jwks_uri, and reports precisely which step failed. It is a live probe only — Save never contacts the IdP and does not require this test to pass, so recovery does not depend on the thing being recovered.

{{/* ---- 6. Sessions ---- */}}

Sessions

{{range .Data.Access.SessionFacts}}{{template "admin-access-fact" .}}{{end}}

Administration is re-derived on every request from the session's verified groups against the current server.auth.admin_groups, so editing that list revokes or grants admin immediately — no re-login, no restart. Group values are captured at sign-in: a change at the IdP (added or removed membership) takes effect when the user signs in again, or when the session expires after server.auth.session_ttl.

Rotating server.auth.session_secret revokes every session and wgt_ token at once. Machine check: curl -b walgit_session=… /_auth/me returns this principal's groups, admin and groups_claim.
