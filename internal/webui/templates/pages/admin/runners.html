Mint a registration token

Single use, 15 minutes. The runner declares its own labels and capacity at registration. Only a host administrator can mint one.

Repository policy

owner/name allows one repository, owner/* allows every repository of that owner; one per line or comma separated, at most 50. Leave both empty and nothing is minted — a token that could never be offered a job is a mistake, not a default.

The runner cannot change its policy: the protocol carries labels, capacity and the fork opt-in only. A registered runner's policy is changed in place on the Fleet card (audited; its current job keeps running). The policy decides which repositories a host is offered — it does not contain the code that runs there.

The image policy is supply-chain hygiene, not a sandbox. The runner host mounts the Docker daemon socket, so a job that reaches it is root-equivalent infrastructure. Fork runs stay off unless the runner opted in, and the allowlist/digest rule narrows which images a workflow may name — it does not contain the code inside them.

Repository policy is tenancy, not isolation. A runner is offered only the repositories its minted policy allows, which keeps one host's code off another team's repositories. It does not contain a job that reaches the daemon: a runner with a socket is root-equivalent on its host, so run untrusted code on a dedicated host (docs/threads.md §8.5, §8.7).

Set both keys on Configuration (one save path; this card never edits). Background: docs/threads.md §8.3 — capacity and isolation · §8.6 — mirroring job images.
