Threads

CI that lives in the repository.

A workflow is a file at .spindle/workflows/ci.yml. A push, a pull request, a schedule or a button creates a run; registered runners execute each job in its own container; every job reports one check into the surface that already gates merges. No marketplace, no cache engine, no second service to operate — and no state outside the object store.

Quickstart

Two files, one runner, one check.

The workflow goes in the repository. The runner is a process you start once. The first push that carries the file triggers it — the workflow is read from the pushed commit.

1. Commit the workflow

Only .spindle/workflows/*.yml and *.yaml are read: one directory, no nesting, no fallback to another CI's directory. Each file is capped at 1 MiB. A file that does not parse creates no runs; its error is shown in the repository's Threads page while the other files keep running.

The file below is complete. It runs on every branch push and every pull request, inside a Go image, and reports the check threads/ci/test.

2. Start a runner

A host administrator mints a one-time registration token at /admin/runners, together with the runner's repository policy: every repository, or an allowlist of owner/name and owner/* patterns. On the runner host — Docker is required, and DOCKER_HOST names the daemon — exchange the token once and then serve:

Labels are exact strings matched as a subset: a job's runs-on must be contained in the runner's declared set. ubuntu-latest is not special here unless a runner declares it. Capacity 1 keeps one job per daemon, which is the isolation-preserving shape for untrusted code. The runner declares and then long-polls; a claim is a compare-and-swap on the queue entry, so any number of runners need no coordinator, and fetching is the heartbeat.

3. Watch it

The repository's Threads page lists runs, the per-file parse errors and the Run workflow control. One run page shows jobs, runs-on, the runner, the check context, step results, artifacts and a live log per job. The commit page shows the same checks in its Checks panel, and the JSON API and spindle threads verbs return the same state.

Key reference

Every key the parser accepts.

The parser is strict. An unknown key is a parse error for that file — never a silently ignored typo. There is no defaults: block, no paths: filter, no matrix include/exclude and no max-parallel.

Triggers

Four events, no tag pushes.

Filters are deliberately small: branch globs use * only, there is no path filter, and a tag push creates no run — so a release process is dispatched, not tag-triggered.

Push. Fires for refs/heads/<branch>. branches matches exact names and * wildcards (release/*); no negation, no **. A merged pull request creates a push run for the base branch. A push authenticated by a job token creates nothing.

Pull request. branches filters the target. types is a closed vocabulary: opened, synchronize, reopened. A same-repository PR runs the head commit's file, trusted, with secrets. A fork PR runs the base branch's file, untrusted, with no secrets and a read-only token.

Dispatch. Typed inputs from the UI, the API (POST …/api/threads) or spindle threads run. Inputs must match the declared schema or the call is 422.

Schedule. Five fields, UTC. Supported: *, numbers, ranges, steps (*/15, a-b/N) and comma lists. Names, macros, L/W/# and six-field expressions are parse errors.

Structural fields — runs-on, container.image, environment — and workflow/job/container env do not take ${{ }}. A dispatch input can choose the environment name only if the job names it literally.

Jobs

Dependencies, matrices, one lock.

A job with no if runs only when every dependency succeeded. Failures propagate as skipped, never as a silent green. A matrix is a simple product. A concurrency group admits one run at a time.

Propagation. A failed, cancelled or skipped dependency skips its dependents and records the reason. A true if runs anyway: always(), failure() or needs.test.result == 'failure'. if: false disables a job without deleting it.

Matrix. Simple product of scalar axes, expanded in alphabetical axis order, values in declaration order. Every cell gets its own job id, check context and MATRIX_<AXIS> variable. The product is capped at 256.

Fail-fast. On by default: a failed cell cancels its siblings. A job-level continue-on-error: true suppresses that, because the failure is tolerated.

Concurrency. One in-flight run per group per repository. A workflow-level group belongs to the run, so sibling jobs do not serialize each other. cancel-in-progress: true cancels the holder. A group that cannot resolve is a parse error or a 422 — never a literal fallback.

The expression subset

A step if can read success(), failure(), always(), cancelled(), github.ref, github.ref_name, github.sha, github.event_name, github.workflow, github.job, github.repository, github.run_id, matrix.*, inputs.*, env.*, steps.<id>.outcome, .conclusion and .outputs.*, with ! == != && || ( ) and string literals. A job if adds needs.<job>.result and needs.<job>.outputs.*.

There is no contains, startsWith, endsWith or format. An unsupported expression is an evaluation error: the step or job fails with the message rather than being silently skipped.

Execution surface

One container, one workspace, your services.

Every job gets exactly one container and one workspace volume. Steps are docker exec invocations inside it, so the toolchain and network namespace persist. Services are sidecars on that job's network.

Image. container: names it; without one the runner's --image is used (default alpine/git, which carries git for checkout). The image must provide what your steps call — a distroless or scratch image has no shell.

Workspace. A per-job volume at /spindle/workspace. The runner mounts nothing else. Workflow-supplied volumes are refused: a bind mount is host filesystem access.

Services. Each entry is one sidecar, reachable at its key on the container port: postgres:5432, never a host port. The runner waits for a declared port or the image's own HEALTHCHECK; 60 seconds without readiness fails the job naming the service.

Environment. Lowest to highest: runner built-ins, workflow env, job env, container env, step env, then secrets by name. Scripts read $GITHUB_SHA, $GITHUB_REF, $GITHUB_WORKSPACE and the rest; they do not get ${{ }} substitution.

Checkout. uses: actions/checkout runs inside the container and clones the run's exact commit with the job token, shallow unless fetch-depth: 0. Any job that pushes needs the full clone. The clone URL must be reachable from inside the container.

The options allowlist is small: --cpus, --memory, --memory-swap, --shm-size, --ulimit nofile=…, --init, --read-only, --user, --workdir. --privileged, --cap-add, --device, --security-opt, every namespace flag and every mount are refused, at run creation and again at plan time.

Steps & actions

Three built-ins, local actions, images.

There is no marketplace. uses: resolves to the three built-ins, a repository-local action, or a container image — and nothing else.

Accepted uses spellings
uses:What happens
actions/checkoutBuilt-in checkout inside the job container. actions/checkout@v4 also resolves; everything after @ is ignored.
actions/upload-artifactUpload files from the job container to the run.
actions/download-artifactDownload an artifact of the same run, under path.
./.spindle/actions/<name>A repository-local action, resolved at run creation from the run commit (composite or docker).
docker://image[:tag|@sha256:…]Run the image as its own container on the job network, with the workspace volume.
anything elseThe step fails: there is no marketplace for remote actions. That includes setup and cache actions.

Composite actions. runs.steps expand in place; each run step must name shell:; an inner uses may only be another local action or docker://. The caller's with: values become INPUT_<NAME> environment variables, and an undeclared input is a named refusal. Nesting is capped at 10 and cycles are refused.

docker:// steps. The image runs as its own container, gets the step environment and INPUT_*, and never the job token or a repository secret. Its $SPINDLE_OUTPUT is copied out and published under the calling step's id.

Outputs. echo "name=value" >> "$SPINDLE_OUTPUT" (or a heredoc). Caps: 50 per step, 100 per job, 64 KiB per value. A reference to an output that was never published fails the step naming it.

actions/cache does not exist. Every job starts cold; reuse a registry image or install in a run step. Artifacts move files between jobs of one run; they cannot cross runs.

Secrets & permissions

Secrets are environment variables.

A repository secret is injected under its own name into every step of a trusted run. ${{ secrets.NAME }} is not substituted — read $NAME. The job token is automatic, short-lived and scoped to one attempt.

Writing. Settings → Secrets, or PUT …/api/threads/secrets/{name}. Write-only: the API returns names and timestamps, never a value. Names match [A-Za-z_][A-Za-z0-9_]{0,63}; values are 1 B – 64 KiB.

Reading. The value is an ordinary environment variable. Guard it: ${TOKEN:?TOKEN is not set} turns a missing secret into a clear failure instead of an empty string.

Masking. Best effort, server-side: exact substring replacement in log lines; values shorter than 4 bytes are skipped. Encoded or split values print. Never write a secret into an output or an artifact — both are data, not logs.

Fork runs. No secrets at all. The payload carries an empty set; a fork can never opt in by editing the file.

The job token. $SPINDLE_JOB_TOKEN always reads its own repository. contents: write adds push. A fork is pinned to read. A protected ref still refuses it, because the principal is ci:<runner>, not the user. A push with it starts no workflow, so a workflow cannot rebuild itself forever.

Approvals and environments

A fork pull request from a first-time contributor is created pending_approval: jobs written, checks pending, nothing enqueued. A maintain or admin approves or denies on the run page (or POST …/api/threads/{run}/approve|deny). The gate applies when the actor has no previously merged PR in the repository; a same-repository PR is never gated. Nobody approves, nothing runs — there is no timeout.

An environment is a deployment target with up to 10 required reviewers (write or more) and its own secrets. A job names one with environment: production; the run pauses until a listed reviewer or a repo admin approves. Environment secrets override repository secrets of the same name, reach only a trusted run with an approved deployment, and never reach a fork run. A job naming an undefined environment fails that job.

OIDC. permissions: id-token: write on a trusted run supplies SPINDLE_ID_TOKEN_REQUEST_URL and a request token; POST an audience for a five-minute signed JWT. write-all deliberately does not grant it.

Artifacts, schedules, retention

Files between jobs; a clock that fires once.

Artifacts. Same run only. Names are unique per run and limited to letters, digits, ., _ and -. Paths are workspace-relative: exact file, directory, */? within a segment, ** across segments, or .. Only regular files; symlinks are not followed. The image needs find and tar. Caps: 256 MiB per file, 2 GiB per run, 1000 files per artifact.

Schedules. Default branch only; a process with the maintain role must be running. A CAS'd watermark fires each tick at most once, so a restart does not duplicate a deploy and a crash loses one tick rather than repeating it. There is no "run now": dispatch the file.

Retention. A terminal run is deleted after threads.retention (default 30 days); logs, jobs and artifacts go with it. Checks do not, so an old required check still gates a merge. retention-days may shorten an artifact's window, never extend the run's.

Recipes

The shapes that cover most CI.

Test-only CI for Go

Tag a release from a dispatch

Tag pushes never start a run. A release is a manual dispatch, and the job creates the tag; the resulting tag push is deliberately silent.

Build an image without a Docker socket

A job container never receives a Docker socket, so docker build has no daemon to talk to. Use a daemonless builder image. Whether it can create namespaces is a property of the runner host — the job cannot request --privileged or capabilities.

From a Forgejo workflow to Threads.

Tests translate almost mechanically. Publishing needs a plan, because four things have no equivalent: tag triggers, path filters, matrix include, and a daemonless builder's host capabilities.

Weave: a test job

The custom CHECKOUT script existed because the image had no Node for a JavaScript checkout action. The built-in checkout runs in the job container, so the token plumbing, the git init and the http.extraHeader all disappear. secrets.GITHUB_TOKEN is not needed.

Scriobh: a matrix release

The original builds four OS/arch pairs with matrix.include. Threads has no include, so the four combinations become one target axis and the step splits it. The cells, the artifacts and the names are the same.

Each artifact name is unique per run because target is part of it. The four cells are exactly the original four; no extra combinations are built.

The safe order

  1. 1

    Tests only

    Replace the custom checkout with the built-in one. Read-only, no secrets. This proves labels, image, checkout reachability and duration before anything can be damaged.

  2. 2

    Matrix and services

    Prove every cell and the database sidecar, still read-only.

  3. 3

    Artifact-producing jobs

    Build, upload, download and verify inside Threads. Still no credentials.

  4. 4

    Keep publishing where it is

    Move the credential only after the spindle job has produced the same bytes twice; run both once in parallel and compare digests, not logs.

  5. 5

    Retire the old workflow

    Only after a release shipped from Threads. The rollback is re-enabling the old file — one revert.

Troubleshooting

Start where it stopped.

The evidence is on the run page: the job's reason, its runs-on, the checkout URL, the step result, and the log. Read those before changing the file.
