# 12 — Web UI: server-rendered pages, htmx, vanilla-ES islands, and the `repos.js` SDK (D-WEB-14)

> Source: MASTER_RUST_SPEC.md §10 (web UI + SDK), §8.8/§8.9 (auth flows and setup recipes consumed by the UI), §9 (wire contract) · Status: normative for the spindle Go implementation.

> **D-WEB-14 (2026-11-19, explicit user request — DEVIATIONS.md):** browser pages are **Go
> `html/template`** rendered by `internal/webui`, progressively enhanced with **htmx 2.0.4 (vendored)**
> and small **vanilla-ES islands** (`web/src/islands/`). The SolidJS SPA, `@solidjs/router`, the
> client data/cache layer and the client-side markdown sanitizer are superseded; user markdown, diffs,
> commit graphs and highlighting are rendered **server-side in Go**. The JSON API and the dependency-free
> `repos.js` SDK (§1) are unchanged and remain the programmatic/agent surface.
>
> **D-WEB-15 (2026-11-20): the SPA is deleted.** `web/src/{pages,components,lib}`, `web/index.html` and
> its vite config are gone; vite remains only as the `@tailwindcss/vite` host that builds `app.css`, and
> `package.json` has no runtime dependencies. `internal/server` no longer has an SPA shell handler, so a
> page path the provider does not answer is the plain 404.

The UI is one server-rendered artifact plus the SDK:

| Artifact | Path | Language | Dependencies |
|---|---|---|---|
| Pages | `internal/webui/templates/**` + `internal/webui/*.go` | Go `html/template` | stdlib only |
| Islands | `web/src/islands/*.js` → `web/dist/ui.js` | vanilla ES modules | none |
| htmx | `web/vendor/htmx.min.js` | vendored file | MIT (no npm runtime dep) |
| Styles | `web/src/app.css` → `web/dist/app.css` | Tailwind v4, CSS-first | dev-time |
| SDK | `web/sdk/src/*.js` → `web/dist/repos.js` | plain ES modules | dependency-free |

The binary embeds `web/dist/` and serves `/_ui/app.css`, `/_ui/ui.js`, `/_ui/htmx.min.js`
(stable names, `no-cache` + ETag), hashed `/_ui/assets/*` (immutable) and `/repos.js` (module MIME is
load-bearing).

## 1. Artifact A — the SDK (`web/sdk/`)

The SDK is a **wire client**, not an app: plain ES modules with zero runtime imports (framework-free,
router-free, no state library).
It is **authored as submodules** under `web/sdk/src/` (user decision — never one huge file) and a dev-time
esbuild step bundles the entry module into the single distribution artifact `web/dist/repos.js`, served at
`/repos.js` (one stable URL, one request for external consumers). The SPA imports the same SDK source
modules (bundled into the app by vite); app and bundle share one source of truth. No IIFE/global build
and no `.mjs` twin — pre-1.0, no-compat: ES modules are the only distribution.

### 1.0 Source layout and the build (normative)

```
web/sdk/src/
├── index.js      entry: re-exports the public surface, creates the default client (window.repos only if unset)
├── core.js       ReposClient: options/base-URL resolution, lane selection (§1.2), fetch wrapper
│                 (credentials/redirect/manual rules), 401→popup single-flight retry
├── errors.js     ReposError (+ notFound/unauthorized getters)
├── sse.js        envelope + frame parser, readSse (also imported by the SPA's data layer — one parser)
├── auth.js       popup flow: openAuthPopup, postMessage wait, probe
├── repo.js       the repo client group: refs/tree/blob/raw/commits/commit/resolve/overview
├── admin.js      create/delete, tasks, ops, policy, settings groups
└── types.js      JSDoc @typedef blocks (§1.1) — editor IntelliSense only, no runtime
```

Build (the whole of `make web`: the stylesheet leg is `vite build` with `@tailwindcss/vite`; the SDK and
island legs are esbuild — devDependencies are `esbuild`, `vite`, `@tailwindcss/vite`, `tailwindcss`; there
are no runtime npm dependencies since D-WEB-15, and the SDK itself stays dependency-free):

```sh
cd web && pnpm install --frozen-lockfile     # devDependencies: vite + esbuild + tailwind
pnpm run build                                # css (vite) → islands (esbuild) → vendor (cp) → sdk (esbuild)
pnpm run build:sdk                            # esbuild sdk/src/index.js --bundle --format=esm \
                                              #   --target=es2022 --minify --outfile=dist/repos.js
```

Rules: `web/dist/` is build output (gitignored; created by `make web`, whose steps are independent —
`build:css` runs with `emptyOutDir: false` so it never wipes the island/vendor/SDK output);
`make build` depends on `make web`; tests import the SOURCE modules directly (§5) and need no build; CI runs
the bundle smoke test only when `dist/repos.js` exists. The stable page assets (`app.css`, `ui.js`,
`htmx*.js`, `concepts/*.gif`) and `/repos.js` stay `no-cache` + strong ETag so a redeploy is picked up on
the next fetch; the `dist/assets/*` prefix stays the immutable lane for any content-addressed file.

### 1.1 Public surface

```js
export class ReposClient { /* constructor(opts), configure(opts) */ }
export class ReposError extends Error { status; message; url; get notFound() {} get unauthorized() {} }
export default ReposClient;   // named exports: ReposClient, ReposError
```

`client.repo("owner/name")` → repo client. Every method accepts trailing `{signal?, onProgress?, headers?}`. Full member list — **copy of the Rust spec §10.1 table, wire-identical**:

| Member | Endpoint |
|---|---|
| `me()`, `signIn()`, `owners.list()`, `owners.repos(o)`, `configure(opts)` | `/api/v1/…` |
| `repo.urls` | `{html, clone, api, raw(rev,path), tree(rev,path), blob(rev,path), commit(sha)}` deep links |
| `repo.get/create/delete` | repo root (`PUT` create write / `DELETE` admin) |
| `repo.createPlaceholder({object_format})` | `PUT …/api?placeholder=true` (issue #210 — the flag ride; `repo.create` stays flag-less) |
| `repos.create({owner, name, object_format?, placeholder?, visibility?})` | `POST /api/v1/repos` twin (issue #210 — new `create.js` submodule; naming validation mirrors `ParseRepoId`; UI-route-collision helper) |
| `repo.refs()` | O(1) head |
| `repo.branches(q)/tags(q)` | paged ref lists (`{q?, prefix?, after?, n?}`; JSON-only accept) |
| `repo.refStream(kind, q, onRef)` | SSE ref stream (`event: ref` … `event: done`) |
| `repo.resolve(rest)` | ref/path split |
| `repo.tree(rev, path)` / `repo.blob(rev, path)` / `repo.raw(rev, path)` | tree/blob/`?raw` |
| `repo.commits({ref, path, skip, n})` / `repo.commit(sha)` | history / detail |
| `repo.overview()` | WAL health |
| `repo.tasks()` / `repo.task(id, onEvent?)` | list / attach (JSON or SSE) |
| `repo.ops.list()` / `repo.ops.run(op, params, onEvent)` | op list / run (SSE events) |
| `repo.policy.{get, put, delete, validate, dryRun}` | policy surface |
| `repo.settings.{get, put(toml, message), delete, effective, history, describe, validate}` | settings surface |

Payloads are plain JSON objects — no type layer, no runtime schema. JSDoc `@typedef` blocks document each shape from spec §9.5 (`Commit`, `TreeEntry`, `RefPage`, `Overview`, `TaskRecord`, `OpSpec`, …) for editor IntelliSense without a type-check step. `ReposError` carries `{status, message, url}` with `notFound`/`unauthorized` getters.

### 1.2 Lane selection (normative, order fixed)

```text
explicit `token` option                    → bearer lane    (Authorization: Bearer, credentials: omit)
page origin == API base                    → same-origin    (session cookie, credentials: same-origin)
else                                       → browser lane   (/{o}/{r}/api-browser/…, credentials: include, redirect: manual)
```

On 401 **or an opaque redirect** (a `redirect: manual` fetch reports `type: "opaqueredirect"` / status 0) in the browser lane: open `<base>/api-browser/v1/authenticate` in a popup (single-flight — if a popup is already open, await the same promise), then `await` a `postMessage` of `{type: "repos:authenticated"}` **from our own origin**, then retry the request **exactly once**. A `304 Not Modified` response resolves the exported `NOT_MODIFIED` sentinel (never throws — the data layer treats it as silent keep-current). `_call` accepts a `cache` fetch-cache-mode option, and `ReposClient.withNoStore(fn)` issues every SDK call initiated synchronously inside `fn` with `cache: "no-store"` + `no-cache` headers (the data layer's mutation-refetch bypass, #41).

**Write-401 carve-out (Forgejo #502):** `_call` accepts `noPopupAuth: true` — the anonymous write-interstitial flow passes it on every write call so a server 401 surfaces as a `ReposError(401)` (the page routes it to `/login-required`) instead of opening the sign-in popup and re-running the write. The pre-flight helper (`web/src/lib/writeGate.js`) prevents the call entirely for known-anonymous viewers; the flag covers the stale-identity remainder. Default path (flag absent) keeps the popup retry byte-identical.

```js
// single-flight popup promise — one per client instance
let popupAuth = null;
function authenticateOnce(base) {
  return (popupAuth ??= new Promise((res, rej) => {
    const w = open(`${base}/api-browser/v1/authenticate`, "repos-auth", "width=520,height=640");
    const onMsg = (ev) => {
      if (ev.origin !== location.origin) return;               // our origin only
      if (ev.data?.type !== "repos:authenticated") return;
      cleanup(); w?.close(); res();
    };
    const timer = setTimeout(() => { cleanup(); rej(new ReposError(504, "popup auth timed out")); }, 120_000);
    const cleanup = () => { removeEventListener("message", onMsg); clearTimeout(timer); };
    addEventListener("message", onMsg);
  }));
}
```

Hazard: a second 401 while a popup is open MUST reuse the in-flight promise (single-flight), never open a second window; a rejected popupAuth clears `popupAuth` so a later call can retry. Use plain `fetch` (NOT `EventSource`) everywhere — the server streams only when `Accept` carries `text/event-stream`, and only fetch lets us set that header plus auth.

### 1.3 Base URL resolution

`configure({base})` option → `<script data-base>` attribute → `import.meta.url` origin (the SDK is a module, so this always works) → page origin. Off-DOM default `http://127.0.0.1:8080` for tests only. Resolution happens at construction and is re-evaluated by `configure`.

### 1.4 Envelope handling

Every GET sends `Accept: application/json, text/event-stream`. If the response `Content-Type` is JSON → parse and resolve. If `text/event-stream`:

1. Read via `response.body.getReader()`; split frames on `\n\n` (CR tolerated), buffer the remainder.
2. Parse each frame's `event:` and `data:` lines; JSON-decode `data`.
3. `notice` / `progress` / `task` → surface through the call's `onProgress` AND the client-global handler set in `configure`.
4. `result` → resolve with its payload (terminal). `error` → throw `ReposError(status, message)`. End-of-stream with no `result` → `ReposError(502, "stream ended without a result")`.
5. Honor `signal` at every read; abort → throw `ReposError(499, "aborted")` (client-side convention, never sent by the server).

### 1.5 Ref stream (`refStream`)

`repo.refStream(kind, q, onRef)` consumes the ref-list SSE dialect (spec §9.3: `event: ref` / `{"name","sha"}` per match, terminal `event: done` / `{"more":bool}`) with **plain fetch** (`credentials` per lane; this endpoint is GET-with-query, so no special headers beyond lane auth). `onRef({name, sha})` is invoked as frames arrive — the UI paints incrementally.

### 1.6 Concurrency (SDK)

Hazard: leaked readers and unbounded parallel streams if callers forget to abort.
Avoidance: every method derives its own `AbortController` from the caller's `signal` and closes the `ReadableStream` reader in a `finally`; `refStream` and task-attach loops return a cancellation function in addition to honoring the signal; at most one popup auth promise per client. Playbook: `13_concurrency.md` (ownership: the caller owns the signal, the SDK owns the reader, the SDK closes it).

## 2. Server-rendered pages (`internal/webui`)

### 2.1 The seam and composition

`internal/pages.Provider` is the seam: `Serve(w,r) bool` answers a page or reports *false without
writing* so the caller falls through, and `BindAuth` hands the server's own authority functions
(`Authenticate`, session refresh, the identity read gate). `internal/server` owns the page shapes:
`pageOr404` for the pure page routes (`/`, `/explore`, `/how-it-works`, `/setup`, the owner/repo page
routes) and `uiOr(fallback)` where a non-page lane shares the path (`/api` docs vs the JSON lane, the
`/*` repo dispatch). A path no provider answers is the plain 404 — the SPA was deleted (D-WEB-15).
`cmd/spindle/webui.go` (`wireWebUI`) binds every group's deps (`BindPublic`, `BindRepo`, `BindCollab`,
`BindForms`, `BindSettings`) once at boot — the binders are process-global and any test that builds the
provider must bind them.

The provider is built in **every boot mode**, including setup-only: `/setup` is the way out of an invalid
config, and `mountSetupOnly` routes **GET and POST** `/setup` through the provider.

### 2.2 Templates

One `html/template` set per page: `templates/base.html` (document, header/nav/footer, `{{template
"content"}}`), every `templates/partials/*.html` (shared blocks), and the page file
`templates/pages/<group>/<name>.html` defining `content`. Shared blocks must live in `partials/` — the
page glob parses `pages/*/*.html` as pages, so a partial there is a page and its defines are invisible to
siblings. The layout model (`PageData.Chrome`: title, path, principal, nav visibility, login href, admin)
is computed from the principal, mirroring the old `navModel` rules.

Template functions are deliberately small: `md`/`mdrepo` (server markdown), `diff`, `graph`/`graphrows`,
`hl`, `rel`, `shortsha`, `dict`, `plural`, `hasPrefix`. **Do not shadow `html/template` builtins**
(`eq/ne/lt/len/index/printf/slice`) — a string-only `eq` once broke every error page that compares an int
status.

### 2.2.1 Repository chrome (every repo-scoped page)

**A page scoped to a repository renders the repository chrome — the masthead (`repo_header`:
owner/name, description, branch/tag counts, stars/watches/forks with their write affordances, Clone) and
the tab strip (`repo_tabs`: Code, Commits, Issues, Pulls, Checks when the repo ever reported one,
Releases, Settings) — above its own content.** The chrome is one component with one active-tab rule, so it
cannot drift page by page: a user moving Commits → Issues → Settings never loses the header.

The attach is structural, not per-template:

- `PageData.Repo` (`*RepoChrome`) carries it and `templates/base.html` renders it above `{{template
  "content"}}`. `s.pageRepo(w, r, p, chrome, …)` is the ONE render helper; `s.page` is
  `pageRepo(…, nil, …)`. A repo-scoped template therefore never includes the chrome itself — and can
  never render it twice.
- `s.repoChromeFor(r, p, owner, name)` is the attach path for a handler whose **read gate already
  passed**: ONE `Summary` read (it performs the refs sync itself) plus the boot-bound projections
  (`CollabCounts`, `ForkInfo`, `ChecksSummary`, `Mirror`, `SocialCounts`, …). `s.repoChromeFrom(…, sum)`
  is the same build for a handler that already holds the summary (the collab gate reads it for the
  feature flags — zero extra store round trips). `s.RepoChromeFor` remains the *gated* seam (it runs
  the principal + visibility gate and the Exists/Sync/Summary pass, and writes the response on failure).
- **Chrome is display data and never a gate.** Build it only AFTER the page's own gate: a denied request
  keeps its exact status/redirect and body (no repository name, description or tabs). A failed summary
  read yields `nil` — the page renders without chrome rather than failing a request that its own gate
  already admitted.
- The active tab is derived from the request path by `repoTabSection` (`/{o}/{r}/<first segment>`), so a
  handler never restates its section: `issues|labels|milestones → Issues`, `pulls|pull → Pulls`,
  `checks|check → Checks`, `releases|release → Releases`, `wal|settings → Settings`,
  `tree|blob|commits|commit → Code`. A feature-disabled tab re-highlights onto Code (#522); `/forks` and
  `/fork` are masthead affordances, not tabs, and keep Code current.
- Exceptions, by design: the repo group's own six pages (tree/blob/commits/commit/wal) include the
  partials inside their `content` and leave `PageData.Repo` nil (one masthead, not two), and the collab
  **error** page (`collab/error`) is a full-page interstitial for gate/role/format failures — it renders
  no chrome, because a denial is exactly the case that must not surface repository metadata.

Testing: `repo_chrome_test.go` is table-driven over every repo-scoped page family (collab list + detail
pages, settings tabs, repo forms) asserting exactly one masthead, the tab strip, and the current tab;
plus the reverse (the Code pages keep exactly one) and the gate (a denied request carries no chrome and
no repository metadata).

### 2.3 Routing and precedence

Routes are `http.ServeMux` patterns on the provider's mux, registered by each group from an `init()`
(`registerGroup`). Static-before-dynamic is the SPA's inventory: `/orgs/new`, `/{owner}/repositories`,
`/{owner}/organizations`, `/login-required`, `/invitations` are literal; `/{owner}/{repo}` is the wildcard
below them. Patterns with the SAME wildcard shape cannot coexist (`/{a}/{b}/{c}` vs `/{owner}/{name}/{tab}`
panics), so keep literal routes literal and push shape-generic families through one dispatcher that writes
nothing on a non-match (the team routes do this). A missing repo/ref/path is a real **404 HTML page**, never
a 200 with a client-rendered error.

### 2.3.1 Route inventory (as implemented)

The **identity-owned** pages — `/keys`, `/invitations`, `/notifications` — are not plain read pages:
each one reads or writes a single principal's own data, so each requires a **signed-in principal**
(auth `oidc`/`token`). The gate is `Server.identityAccessFor` (`internal/webui/server.go`), not the
`anonymous_read` flag: a signed-out caller gets the same 401 the JSON twin answers, and an instance
with authentication disabled (`mode` `""`/`none` — no identity exists) renders the shared
`partials/identity_notice.html` callout pointing at `/setup` instead of a management form nobody
owns; their writes answer 401 (signed out) / 403 (auth disabled) before any service call. The primary
nav carries `explore` only — plus `setup` while unsecured, for first-run discoverability; for a
signed-in principal keys/invitations/setup live in the identity menu (setup admin-only).

Read pages (`GET`): `/`, `/explore`, `/how-it-works`, `/api`, `/new`, `/import`, `/orgs/new`, `/keys`,
`/invitations`, `/notifications`, `/login-required`, `/setup`, `/{owner}`, `/{owner}/repositories`,
`/{owner}/organizations`, `/{owner}/settings`, `/{owner}/teams/{slug}`, `/{owner}/{repo}` (code),
`/tree[/{path}]`, `/blob/{path}`, `/commits`, `/commit/{sha}`, `/wal`, `/issues`, `/issues/{num}`,
`/pulls`, `/pull/{num}` (+ `/commits`, `/files`), `/checks`, `/checks/{sha}`, `/releases`,
`/releases/{tag}`, `/forks`, `/labels`, `/milestones`, `/settings[/{tab}]`, `/fork`, `/issues/new`,
`/pulls/new`, `/releases/new`.

Writes post to sibling paths on the page that owns them (`…/close`, `…/merge`, `…/reviews`,
`…/threads/{id}`, `…/labels`, `…/milestones/{id}/state`, `…/settings/{tab}`, `…/releases/{tag}/assets`,
the `star|unstar|watch|unwatch|tag` toggles, owner profile/avatar verbs, notification/invitation state
changes). Three read fragments serve htmx directly: `/checks/{sha}/contexts`,
`/pull/{num}/threads/{tid}`, `/pull/{num}/merge/task`. Shape-generic families (teams) go through one
dispatcher (§2.3).

### 2.4 Gates (exact parity with the API)

`s.gated` applies the require-read rule (`anonymous_read`); `s.repoVisible` applies the repo read gate —
the identity verdict runs **before** the anonymous flag (Forgejo #345), so a public repo stays readable
under `anonymous_read=false`. Per-action role floors (read/triage/write/maintain) are enforced in the
handlers, and feature flags hide only creation affordances. A page URL has no privilege of its own: it
must reproduce the gate its API twin enforces.

### 2.5 Writes

Forms POST/PUT/DELETE to sibling paths (page URLs stay GET/HEAD). Every write: `ParseForm`, a
**same-origin check** (`Origin`, falling back to `Referer`, fail-closed when both are absent), the
service call, then **303** back to the page (the SPA's redirects) or `HX-Redirect` for htmx posts.
Validation errors re-render the page with 400/422 and the submitted values; authority errors keep
401/403/404; a missing service renders the honest "not wired" card (never a dead button). Destructive
actions require a typed confirmation (`data-danger-confirm`), re-validated server-side.

### 2.6 htmx — and what it is not

htmx is vendored and loaded globally; pages use it for partial updates (`hx-post`, `hx-target`,
`hx-select`), navigation stays plain links (boost is not enabled while the SPA fallback exists), and
events drive refetches (`hx-trigger="ui:sse-… from:body"`). The **SSE transport is not htmx**: its
extension cannot POST, set headers, read JSON payloads, or tell a 401 from a drop, so
`web/src/islands/sse.js` keeps a fetch stream (cookies, coalesced invalidation, 1s→30s backoff,
`ui:auth-required`).

### 2.7 Islands

`web/src/islands/` is the entire client behavior surface: `theme`, `menus` (the popover contract),
`copy`, `autogrow`, `selection` (line selection + `#L` anchors, toggling the shipped `line-hl` class),
`sse`, `tasks` (the `/import` progress card: bars + log tail, terminal navigation to the imported
repo, and an honest failure/no-longer-tracked card — pure helpers under `node --test`), `danger`,
`submitkeys`. `index.js` boots them idempotently on `DOMContentLoaded` and after every
htmx swap (`htmx:afterSwap`/`afterSettle`); each island marks the nodes it owns. No client data layer,
no router, no framework.

### 2.8 Server renderers (the XSS boundary)

`internal/webui/{markdown,diff,graph,highlight}.go` replaced the browser libraries. Markdown escapes all
text and allows only `http`/`https`/`mailto`/relative links; diffs are parsed into typed lines and
rendered per cell; the commit graph is emitted as SVG; highlighting emits escaped token spans. **Never
pass user-derived bytes through `template.HTML`**, and never reintroduce a client sanitizer
(marked/DOMPurify are gone by D-WEB-14).

### 2.9 URL state replaces SPA memory

Client-only view state is now a query parameter: `?graph=1` (commit graph), `?doc=<name>` (directory
docs), `?view=code` (markdown code view), `?all=1` (all WAL segments), `?state=`/`?after=` on
notifications, `?skip=`/`ref`/`path` pagers. Selected lines ride `#L<n>[-L<m>]`. Nothing is persisted
locally.

### 2.10 Setup-only mode

The provider answers `/setup` in setup-only mode with the banner and boot errors, and its **POST**
(validate/save) is the recovery path: a saved valid file returns the process to a normal boot. Only the
`setup*` deps are bound there; every other page is outside the setup-only route set (503 by design).

### 2.11 Testing

Page handlers are tested with `httptest` (status, parsed landmarks, classes, hrefs, form fields, gate
failures) plus `golang.org/x/net/html` where structure matters; the package holds the same ≥95 % gate as
every other `internal/...` package. Pure island logic (SSE framing/backoff/coalescing, SDK request
shaping) stays under `node --test` with `web/test/unit/*.test.js`. Rendered verification (390 px and
desktop, real server, Chromium) is required for any UI change — a DOM assertion is not a rendered check.

## 2b. Historical: the SolidJS SPA (deleted by D-WEB-15)

The pre-migration UI was a SolidJS SPA (`web/src/**`, `solid-js` + `@solidjs/router` + marked +
DOMPurify, vite-built shell) whose per-page contracts (landing, owners, create form, repo chrome,
blob/commit rendering, WAL/settings, setup) were realized as the Go templates and handlers described
in §2. The app shell, client router, data/cache layer and client markdown sanitizer are gone; the
route inventory now lives in §2.3.1 and the decisions in DEVIATIONS.md (D-WEB-6/-7 superseded by
D-WEB-14; D-WEB-15 records the deletion). Do not extend the old shapes.

## 3. Serving from the Go binary (embedding contract)

The built UI is embedded; pages are rendered by Go at request time (D-WEB-14), so the shell is no longer
served from disk:

```go
//go:embed all:dist
var web embed.FS   // dist/app.css, dist/ui.js, dist/htmx*.js, dist/repos.js, dist/assets/*,
//                  dist/concepts/*, dist/.keep — dist/ is build output (`make web`)
```

| Path | Cache behavior |
|---|---|
| `/_ui/assets/*` (content-hashed, immutable) | `Cache-Control: public, max-age=31536000, immutable` |
| `/_ui/app.css`, `/_ui/ui.js`, `/_ui/htmx.min.js` (stable names) | `Cache-Control: no-cache` + strong ETag |
| every rendered page | `Cache-Control: no-cache` + strong ETag (a deploy is visible on the next request) |
| `/repos.js` (SDK) | `Cache-Control: no-cache` + ETag; module MIME is load-bearing |

Compression: `gzip` via server middleware for text assets (`text/*`, `application/javascript`,
`application/json`, `text/css`) when `Accept-Encoding` contains `gzip` and the body is ≥ 1 KiB —
on-the-fly `gzip.Writer` level 6, `Vary: Accept-Encoding`, no brotli, no precompressed siblings.
`image/*` (the landing concept GIFs) passes through uncompressed. The `X-Walgit-Capabilities` edge
contract and route registration are specified in `06_server_http.md`; API endpoints in `07_api.md`.

## 6. Dogfood rule

The JSON API and the `repos.js` SDK are the **programmatic surface** (agents, scripts, integrations) and
stay exactly as specified in §1; the SDK remains dependency-free and is the only consumer-facing wire
client. Server-rendered pages do **not** HTTP-loopback: a page handler reads the same service layer the
API handler reads (repo view, feature services, store seams), so the page and its API twin cannot drift
on data while neither pays a transport hop. Client-side `fetch` is limited to the island SSE reader
(§2.6) and the SDK — CI can grep for `fetch(` outside `web/src/islands/sse.js` and `web/sdk/`.

### Concurrency

Hazard: an SSE reader leaks when its element is swapped out mid-stream, and a reconnect storm can turn
one dropped stream into a request flood.
Avoidance (`13_concurrency.md` ownership/cancellation rules): each `[data-sse]` element owns exactly one
`AbortController`, and so does each `[data-task-id]` progress card; `htmx:beforeCleanupElement`/
`afterSwap`, the islands' `cleanup()` and `pagehide` cancel it, and the fetch reader's loop exits on
`signal.aborted` (one closer). Invalidation frames are coalesced with a trailing 250 ms window (bursts
collapse into one refetch), reconnect uses capped exponential backoff (1 s→30 s, reset on the first
frame), and a 401 stops the stream and dispatches `ui:auth-required` instead of retrying forever; the
task island additionally bounds consecutive errors (5) and treats a 404 as terminal (the ring is pruned
past retention, so retrying cannot help). No unbounded buffering: frames are parsed as they arrive and
the effects are DOM refetches, not client caches.
